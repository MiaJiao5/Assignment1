# Assignment 1 — Why Are We Here?

对于设计师或艺术家而言，代码从来不是枯燥的技术苦差事，而是一只能够将抽象设想绘制并变成现实的画笔。那么如何使用这只画笔就变得尤为关键。尽管现在的 AI 能够根据人类地自然语言指令生成各种内容，但其底层逻辑依然植根于代码。如果使用者对代码完全缺乏理解，盲目让 AI 代劳，就像让一位体育老师去充当真实战场上运筹帷幄的将军。由于对战术和军队一无所知，他将无法长久地指挥队伍并赢得胜利。

回想起自己最初接触计算机参数化时，正应了 Dylan Beattie (2019) 在其演讲《The Art of Code》中所提到的那样，“代码就像是一片雪花一样，你每次都像是在开盲盒。”在运行代码之前，你对最终的视觉呈现往往毫无预设。这让我想起大学第一学期初次使用 C4D 时，通过参数随机生成艺术化形状的经历。每次调整参数，那些有机排列的单元体便以一种完全不同于人类思维的逻辑组合在一起，往往会碰撞出一种奇特的美感。

正如 Dylan Beattie 在演讲 The Art of Code 中所说的那样，“代码就像是一片雪花，每次运行都像是在开盲盒”——在代码执行之前，你对最终生成的形态往往毫无预设。这让我不由自主地想起自己初次尝试用 C4D 的参数随机生成艺术形状的经历。每次微调参数，那些有机排列的单元体便以一种全然不同于人类的逻辑组合在一起，奇迹般地碰撞出一种奇特的美感。这种不可控的随机性，一方面瞬间点燃了我对机械逻辑的好奇与着迷；另一方面，由于彼时的自己对底层原理一无所知，那些参数又像是一个危险的潘多拉魔盒——我无从预知结果是好是坏，一切游离在失控边缘。正是这种由陌生带来的未知感，让我在很长一段时间里，对代码始终怀有一种深深的敬畏与恐惧

近两年，随着 AI 技术的发展，编程的门槛变得友好了许多，我也开始逐渐尝试用 AI 创作游戏、视频、网页等各种内容。但在实际操作中，痛点依然明显：第一，AI 虽能高效搞定前端的视觉呈现，但一旦涉及上线、部署等底层的硬件和网络框架，我就会束手无策；第二，在需要进行精细化调整时，单纯通过自然语言与 AI 反复沟通不仅耗时，而且并不准确。相反，如果我对编程本身有一定的认知，就能以极高的效率精准定位并解决这些问题。

经过前两节创意编程课的实践，这种状况有了较为实质性的改变。我已经成功通过 VS Code 将本地应用文件上传到 GitHub 仓库，并通过 Cloudflare 顺利发布了公共网站。在这个过程中，我对本地与云端的联合部署以及 Python 代码的运行逻辑有了全新的理解，曾经对代码的恐惧也在一次次敲击键盘和成功部署中烟消云散。可见，只有当你对编程语言有了一定理解后，才能真正跳出工具的局限，基于底层的框架与知识，去完成更具掌控力的创作。

归根结底，在 AI 时代学习编程，绝不是什么过时的行为，而是为了让创作者更高效地握紧那支属于自己的笔，用更高效的方式将审美与灵感推向极致。我想，这就是我们为什么会在这里的原因。
